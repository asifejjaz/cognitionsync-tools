# Filework

A standalone React/TypeScript file toolkit. Release scope and the persistent 120-idea backlog are in [ROADMAP.md](ROADMAP.md).

Test release: https://aitools.cognitionsync.com. Source: https://github.com/asifejjaz/cognitionsync-tools.

## Run

Node 24 and pnpm are required.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Open http://localhost:5173. If occupied, run `pnpm exec vite --host 0.0.0.0 --port 5174 --strictPort`.

```sh
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
pnpm build
pnpm preview
```

Browser tests start or reuse the dev server automatically. Override `PLAYWRIGHT_BASE_URL` for an already-running server on another port. `node scripts/generate-fixtures.mjs` regenerates the original sample DOCX, Markdown, and PDFs. Generated sample assets are checked in so production does not require this command.

The production smoke test runs separately with `FILEWORK_PRODUCTION_URL=http://127.0.0.1:4173 pnpm exec playwright test production.spec.ts` while the preview server is running (set the environment variable using your shell's syntax). It exercises the built assets with the same CSP configured for Nginx. See [SECURITY.md](SECURITY.md) for the dependency audit and launch review notes.

## Deployment

```sh
docker build --build-arg SITE_URL=https://your-real-domain.example -t filework .
FILEWORK_IMAGE=filework docker compose -f deploy/compose.yaml up -d
```

Compose binds to host loopback by default. If the reverse proxy runs in Docker, use a verified private host gateway through `BIND_IP`; container loopback is not host loopback. Place behind a TLS reverse proxy or CDN. Build uses `SITE_URL` for canonical links and sitemap; omit it during local development. Production contains dedicated route HTML, browser code, and static sample files. No upload API, credentials, user database, analytics, or advertising account is configured.

For a low-cost VM deployment, build on a trusted development machine, transfer only `dist/` and `deploy/`, and build the runtime using `docker build -f deploy/Dockerfile.prebuilt -t filework .`. See [deployment.md](docs/deployment.md) for the tested workflow and rollback considerations, [capacity-and-security.md](docs/capacity-and-security.md) for the resource/abuse assessment, and [reuse research](docs/reuse-research-2026-10-09.md) for upstream candidates.

## Architecture And Limits

- `src/catalog.ts`: route/tool metadata.
- `src/lib`: image, PDF, document, and download operations.
- `src/components`: previews and tool-specific controls.
- `scripts/prerender.mjs`: route-specific metadata/static shell, not full SSR.
- `tests`: structural PDF unit tests and real browser conversion tests.

Processing stays in the browser. Limits: 25 MB/file, 100 MB/batch, 30 files, 24 megapixels/image, 100 pages/PDF, 150 pages/merge. Large HEIC decoding can still pressure memory before pixel limits are known; mobile devices need conservative limits. Conversion flattens image metadata and exports the first still image from HEIC containers. Animated images are not preserved.

PDF tools preserve ordinary pages, not all bookmarks, forms, attachments, or document-level metadata. Inspect these after merge/split. Existing certificate signatures may be invalidated by edits. Annotation text currently uses a Latin font. DOCX conversion is structural, not pixel-identical Word layout. Markdown image references become captions rather than external downloads. Size-limit compression may reduce dimensions, and reports this explicitly.

Rendering uses PDF.js, PDF edits use pdf-lib, HEIC uses heic-to/libheif, DOCX uses Mammoth/Turndown, and Markdown PDF uses pdfmake with its bundled Roboto fonts. Dependency upgrades should rerun conversion tests, not only type-check.
